01  github.com issue #14370, staff comment Nov 5 · 69 comments

🔁 Postman reverts the forced agent-plugin install: "we are reverting this change"

Four days after No. 032’s story - Postman auto-installing Codex and Claude plugins and self-approving a hook, documented in GitHub issue #14370 - a Postman team member posted the company’s answer: revert now, redesign later. The issue is closed.
SCENE

Last week, developers opening Postman found plugins for AI coding agents they never asked for, wired in with a self-approved hook - and they did the unglamorous thing that actually works: they filed a public, specific, reproducible issue on the vendor’s own tracker and kept it factual. Sixty-nine comments later, on Thursday at 03:46 UTC, GitHub user preethammavin, marked as a Postman team member on the issue, replied.

THE THING

The reply, verbatim: "We intended this change to simplify the setup for developers who use agents to build APIs with coding agents as we see many people struggling in wiring these up. Installing skills for coding agents is a new way of working with Postman and we thought that the in-product and website messaging conveys the intent. Based on the feedback from the community, we understand this wasn’t the case so we will be re-designing the experience with the right level of control. In the meantime, we are reverting this change." The issue was closed later on November 5. Two things the reply does not say: whether already-installed plugins and the self-approved hook get removed by the revert, and what "the right level of control" will mean in the redesign. This is the fourth consent-thread story in a week and the first full revert: Postman’s silent installs (No. 032), the Codex training toggle (No. 032, still unexplained by OpenAI), Gemini’s training fine print (No. 033) and Claude Code’s outbound email (No. 034, still without an official statement) all stay open in the background.

✂️ STEAL IT

Steal the playbook: the complaints that moved a vendor in four days were public, reproducible and on the vendor’s own tracker - exact versions, exact behavior, no outrage required. And steal the audit habit: a revert announcement is not a cleanup. Anything already installed stays installed until you check.

Try today  VERDICT

Do the TRY section below: update Postman, then audit what the install actually left behind - agent plugins, hooks, and settings you never chose. It fails you if the redesign ships "the right level of control" as another default-on, and the thread is where that will show first.

👻 Libghostty 1.0: the terminal inside your IDE is now one stable C library

Mitchell Hashimoto’s libghostty-vt, extracted from the core of Ghostty, hits 1.0 with a stable, CI-enforced C ABI. JetBrains IDEs already run on it - 12.5 million active users, per a JetBrains report he cites - and Neovim has an approved PR swapping libvterm for it.
SCENE

A year ago, Hashimoto used a bug in JediTerm - the terminal emulator inside JetBrains IDEs - as his example of why terminal emulation is hard to get right. Today the terminal in every IntelliJ, PyCharm and GoLand runs on his library instead. "More people today use a terminal powered by libghostty than use Ghostty the application, by a very large multiple."

THE THING

The 1.0, per the post: libghostty-vt is a portable C library for terminal emulation with a stable ABI - every object an opaque handle, hundreds of values behind a small set of enum-keyed getters and setters, symbols versioned so the loader refuses mismatches, and the policy enforced in CI with libabigail on Linux and golden manifests on macOS and WebAssembly. MIT licensed, no copyleft anywhere in the tree, dependencies in a machine-readable SPDX manifest, signed source tarballs built for offline distro packaging. The adopter list is the argument: JetBrains (over 12.5 million active users, "based on a report by JetBrains"), an approved Neovim PR replacing libvterm that closes a ten-year-old issue about reflowing scrollback on resize - maintainers were waiting on exactly this tagged release - KDE developers experimenting with a Konsole replacement, Vercel’s Turborepo, devenv, Antithesis (which used it to fuzz TUI programs and found real bugs in btop), OrbStack, an Emacs port, a WASM build with an xterm.js-compatible API, and "agentic" coding tools like herdr and cmux that embedded it rather than write yet another emulator.

✂️ STEAL IT

Steal the design: ABI stability as a feature, not an afterthought - opaque handles, enum-keyed extensibility so new values never break old callers, versioned symbols, and CI that treats an ABI break as a build failure. That is what turns a personal project into infrastructure a hundred products can bet on.

Try today  VERDICT

If you maintain anything that embeds a terminal - a TUI, a CI dashboard, an agent tool - evaluate libghostty-vt before forking xterm.js or libvterm; the WASM build drops into an xterm.js-shaped API. It fails you if you do not ship a terminal, and on Neovim nothing changes until the PR merges after this tag.
