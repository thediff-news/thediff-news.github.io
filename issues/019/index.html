01  HN: 950+ points across threads · Wiz Research + php.net, Oct 21 · image: Wiz

🐘 AI found the worst PHP bug in a decade

Two CVEs in the PHP engine itself, every version back to 5.4, pre-auth RCE on WordPress, Drupal and Joomla. Patches are out.
SCENE

On August 19, four Wiz researchers, Sagi Tzadik, Shir Tamari, Nir Ohfeld and Tomer Schwartz, found the first of these bugs using Wiz Atlas with Gemini 4 Argon and GPT-5.6 Sol. The next day they had unauthenticated remote code execution against Drupal. The day after, WordPress. On August 24 they reported to PHP, and yesterday the fixes shipped: 8.5.12, 8.4.27, 8.3.36 and 8.2.35. Wiz calls the findings among the most severe in PHP history, and arguably in software history. Their reasoning: the flaws sat in the codebase for over a decade, but chaining them into an exploit was at the edge of what human researchers could do, and frontier models removed that barrier.

THE THING

The bugs are memory-safety issues in how PHP handles fatal errors, especially out-of-memory errors, mid-request: a request dies, the engine keeps a corrupted internal state, and a later request inherits it. CVE-2026-109618 is a use-after-free in the session upload-progress unserializer; demonstrated impact is remote process-memory disclosure and pre-authentication RCE on WordPress, Drupal and Joomla, independent of the application on top. CVE-2026-109619 is a second fatal-error memory bug. PHP runs what Wiz puts at 70% of all websites. Within hours of disclosure, exploit POC repos passed 900 stars, and OpenAI published php2shell-checker: Codex skills plus a node script that check a URL or a local binary against the patch cutoffs.

✂️ STEAL IT

Steal the response speed. Disclosure to public exploits to an official agent-checkable verifier, all inside a day. When the next one hits your stack, "are we affected" is a question you should be able to answer before lunch, so build that muscle now: an inventory of what runs where, and one command that checks it.

Try today  VERDICT

If you run PHP anywhere, you want 8.5.12, 8.4.27, 8.3.36 or 8.2.35, and Wiz says patch immediately. OpenAI’s checker answers "is this URL or binary vulnerable" in one command. It fails you if your PHP comes from a Linux distro that backports fixes: the version string will lie to you, so check your distro’s tracker instead.

02  HN: 436 points · SafeDep analysis, Oct 21 · image: SafeDep

☠️ LiteLLM 1.107.0 on PyPI was a credential stealer

All seven wheels installed a stealer and a backdoor that run at every Python startup. PyPI has pulled the release.
SCENE

Somewhere between the LiteLLM GitHub repo and PyPI, release 1.107.0 picked up a passenger. The upstream source is clean. The wheels on PyPI were built from an attacker-modified source with one extra line in pyproject.toml’s maturin section: data = "cook". SafeDep’s Kunal Singh took the release apart yesterday and found what that line smuggled in.

THE THING

Three files land in site-packages with every wheel, Linux, macOS and Windows alike. The first is cook.pth, and the trick is unpleasant: any line in a .pth file that starts with import runs at every Python process startup on the host, whether or not anything ever imports litellm. That runs the credential stealer. The second payload is a backdoor in sitecustomize.py, and a daemon re-runs the stealer hourly, reading its next server address from a file on GitHub and executing whatever it downloads. PyPI has since removed the release; 1.106.2 and the two 1.107.0 release candidates are clean, and so are the pinned companion packages. How the build pipeline was compromised is open: a stolen maintainer or bot credential, or a poisoned build reference, fits the evidence, and SafeDep says only BerriAI’s pipeline logs can settle it.

✂️ STEAL IT

Steal the audit habit: diff the wheel against the repo, not the repo against itself. A .pth file containing an import line is an execution primitive, so grep your site-packages for them the way you already watch postinstall scripts in npm.

Try today  VERDICT

If anything in your fleet installed litellm 1.107.0 while it was live, treat the host as compromised: its credentials are gone and the daemon survives uninstall, so rotate and rebuild rather than pip remove. The clean pin is 1.106.2 and SafeDep’s post has the indicators of compromise. It fails you if you only read requirements.txt; the wheels went everywhere pip goes.

04  HN: 305 points · Railway disclosure, Oct 21 · image: Railway

🚨 Railway pauses every deploy after an env-var breach

Attackers may have decrypted customer environment variables, apparently hunting AI inference keys. Railway tells everyone to roll secrets.
SCENE

Yesterday morning Railway detected anomalous activity in the systems that store customer environment variables. Its investigation so far: an unauthorized third party may have accessed encrypted environment variables and, for some, walked away with the decrypted contents. The company paused all deployments while it investigates, which means no Railway customer can ship until builds resume.

THE THING

The motive line in the disclosure is the part to read twice: Railway believes this is part of a series of attacks targeting platform companies with the aim of compromising AI inference providers, and it has notified those upstream providers to revoke keys proactively. Environment variables are where API keys, database passwords and registry credentials live, so the advice is blunt: roll all of them, and review logs on the downstream services. Railway says the impact may be limited to a subset of users, that affected customers will get direct email, and that updates land on the announcement and status.railway.com.

✂️ STEAL IT

Steal the blast-radius map. Your PaaS environment variables are a key store your upstream providers never agreed to trust. Write down which keys sit where, and what rolling each one breaks, before someone else schedules the fire drill.

Try today  VERDICT

If you deploy on Railway: roll every env var and private registry credential now, then watch status.railway.com for the builds-restored notice. It fails you if you rotate keys you have not inventoried; the outage you cause will be self-inflicted, so map first, then rotate fast.

05  HN: 174 points · mitmproxy commit, 23:36 UTC Oct 21 · card: GitHub

🔑 A compromised CA key is now a mitmproxy feature

Maximilian Hils committed the leaked eMudhra private key to mitmproxy so you can test whether your clients still trust it.
SCENE

At 23:36 UTC last night, mitmproxy maintainer Maximilian Hils landed a commit with an unusual payload: the actual private key of a compromised eMudhra intermediate CA, embedded in mitmproxy/certs.py, with a link to the public proof of compromise. The new --emudhra option makes the proxy sign TLS certificates with that compromised key.

THE THING

The point is testing, not mischief. If your browser, your curl, your embedded client still accepts a certificate signed by the revoked eMudhra intermediates, mitmproxy can now show you in one run, no external test server needed. A companion change, #8499, updates the certifi dependency to remove eMudhra CAs from the precompiled binaries, so the tool itself stops trusting the corpse it ships. The option is in main, tagged unreleased; you run it from source today.

✂️ STEAL IT

Steal the regression-test pattern. When a trust anchor dies publicly, its corpse becomes the perfect fixture: commit it, and make "we no longer trust this" a test that runs in CI instead of a hope.

Try today  VERDICT

If you test TLS clients for a living, this is the fastest way to check revocation hygiene across your fleet, straight from mitmproxy’s main branch. It fails you if you wait for a tagged release; nothing is versioned yet, and the option name says exactly what it does.

🎛️ harp: a mission-control sidebar for coding agents

Run many Claude Code and Codex agents side by side, with one sidebar that tells you which one needs you. Two days old, 540 stars.
SCENE

The repo appeared Tuesday and passed 540 stars by this morning: harp, an unofficial fork of Warp rebuilt around a single observation. Running one coding agent is a conversation; running five is a management problem.

THE THING

The pitch is a sidebar that runs many Claude Code and Codex agents side by side and, crucially, tells you which one needs you. Agents park in different states, waiting for input, running, done, blocked, and harp’s entire design bet is that your attention is the scarce resource, not tokens. It is an unofficial fork, two days old, AGPL-3.0, so treat stability and governance accordingly.

✂️ STEAL IT

Steal the attention model. The useful primitive in any agent fleet is not parallelism, it is the "which one is waiting on me" queue. Whatever you orchestrate with, build that view first; the rest is terminal multiplexing.

Try today  VERDICT

If you already run Claude Code or Codex in parallel terminals, harp is a weekend install. It fails you if you need a maintained vendor relationship: this is a personal fork with a copyleft license, and the README is the whole support department.
