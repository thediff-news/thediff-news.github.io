01  HN thread 50456791, 321 points at 06:27 IST · Google blog, Nov 11 · LangChain + Vercel on day one

🎯 Google’s Gemini Decision 1 scores 1,000 questions in one 200 ms pass - and Simon Willison already tested it

The Decisions API answers yes/no, choice and rubric questions over one multimodal input in a single forward pass: no text generated, output tokens free. Willison’s same-day test: calibrated probabilities where rivals return hard zeros and ones.
SCENE

Simon Willison spent the evening passing his own stomping-robot video to Google’s newest model alongside four questions: does it have a dragon, a robot, is it set in France, in the USA. Back came probabilities, not prose: dragon 0.0498, robot 0.9234, France 0.0833, USA 0.9230. His post notes that the two rival decision models he has used, Jev and OpenAI’s, return hard 1.0 or 0.0 on yes/no questions; Gemini "insists on being a little less confident than that."

THE THING

The Decisions API, announced Nov 11 and powered by the new Gemini Decision 1 model (gemini-decision-1), is built for control flow: one shared input - text, image, audio, video or PDF, up to 256K tokens - plus up to 1,000 independent yes/no ("noul"), multiple-choice or rubric questions, scored in a single forward pass with no text generated. Google’s numbers: 50-100 ms of model compute, 150-250 ms end to end, nearly flat from 1 to 100 questions per request, $0.10 per million input tokens and zero output tokens billed; it also claims the lowest calibration error across its benchmark suite and "nearly 5x cheaper" than Gemini 3.5 Flash-Lite through the Interactions API - its benchmarks, its comparison. Willison’s comparisons: the API mirrors Jev down to reusing its "noul" term for a yes/no question, matches OpenAI’s GPT-6 Luna decision model on price (Jev remains cheapest at $0.042 per million), and only Gemini handles audio, video and PDFs. Google’s Philipp Schmid writes that Gemini Notebook already routes prompts across model tiers through the endpoint and Stitch applies voice edits to wireframes in real time; LangChain’s integration docs and a Vercel AI Gateway listing were live the same day.

✂️ STEAL IT

Steal the split, even if you never call this API: bounded questions - which tool, does this pass policy, route where - are not generation tasks, and pricing them as generation is how you end up paying chat-model rates for a yes. If you adopt it, route on the confidence score each answer carries: high confidence fires the code path directly, low confidence escalates to a reasoning model or a human, which is how Google says Notebook uses it.

Try today  VERDICT

A free AI Studio key is enough to replace one brittle JSON-parsing router with a single noul or choice call and measure the difference. It fails you when your questions depend on each other - they cannot see one another by design - or when you need reasons, not scores. The calibration and 5x claims are Google’s own; Willison’s test is one evening and one video.

02  GitLab guide, Nov 11 · changelog checked 06:27 IST: 2.1.322, no fix

🔐 Day 5 of the exposed settings files: GitLab shipped the fix Anthropic hasn’t - a push rule that rejects the file

GitLab’s guide tells every group owner to block .claude/settings.local.json at push time and clean the history first. Anthropic’s changelog, read this morning, is still 2.1.322 - no fix, five days after prototypes were promised.
SCENE

A GitLab group owner opens Settings, Repository, push rules, and pastes one line - (^|/)\.claude/settings\.local\.json$ - and from then on any push that tries to add the file, in the root or any subdirectory, on any branch, is rejected before it lands, with a message naming the pattern. That is the centerpiece of the guide GitLab published yesterday for the exposed-settings-files story: four layers of defense written for group owners, with the note that GitLab has confirmed its own infrastructure secrets are protected.

THE THING

The guide’s logic, in GitLab’s framing: Claude Code excludes the file only through the developer’s personal global git configuration, which "stays on that laptop" and does not travel with the repository. So: add the line to each repository’s .gitignore - group file templates make every new project inherit it - then enforce with a push rule on Premium or Ultimate. Two caveats GitLab flags: the rule only inspects files being added, so existing copies and their history have to be cleaned first, and a group-level rule does not retro-apply to existing projects, so the guide ships a loop over group project IDs. It cites Apiiro’s count: 104,185 public copies of the file, 1,122 holding at least one secret. Anthropic’s side, five days after the Hacker News comments attributed to Claude Code head Boris Cherny promised to "prototype" secret scanning and better auto-mode catches: the changelog, read in full at 06:27 IST, sits at 2.1.322 - Vertex fast mode, nothing on settings.local.json or secret scanning.

✂️ STEAL IT

Steal the ordering: clean first, block second. A push rule only inspects added files, so blocking before cleanup freezes the leak in history, where scanners still find it. And steal the regex even if GitLab is not your platform - the same filename check works as a pre-commit hook or a CI gate anywhere.

Try today  VERDICT

The .gitignore line costs nothing on any tier, and the ten-minute cleanup needs no vendor. Then watch the Claude Code changelog for the actual fix: prototypes were promised Nov 7, and until one ships, the defense belongs to you and your platform - GitLab just showed what that looks like.
