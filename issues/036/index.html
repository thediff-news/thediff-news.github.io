01  thehackernews.com on Apiiro’s research, Nov 7 · HN: 251 points at 06:26 IST

🔐 "Yes, and don’t ask again" - Claude Code saved the password with the command. 1,122 of those files are public

Apiiro says approving an exact command in Claude Code can store it verbatim - secrets included - in .claude/settings.local.json, and its scan found 1,122 public copies on GitHub holding at least one secret. One notified company confirmed its key was live. The figures are Apiiro’s, reported by The Hacker News.
SCENE

A developer runs one command with a password in it - a database URL, an API key, a token. Claude Code asks before running it, and the developer clicks the productive-sounding option: "Yes, and don’t ask again." From then on that command just runs. What the click also does, per Apiiro’s research: save the exact command, word for word, into a project file called .claude/settings.local.json - the secret sitting inside it in plaintext. Then the file gets committed and pushed, and anyone on GitHub can read it.

THE THING

The mechanism, as reported: exact-command approvals are stored verbatim; pattern approvals like npm test * are not the problem. Claude Code does try to protect the file - on first write in a git repo it adds it to the user’s global git excludes, per Anthropic’s settings documentation - and yet Apiiro’s scan still found 1,122 public copies holding at least one secret each. Apiiro did not test whether the secrets still work; one company it notified earlier in the week confirmed its key had been live. The researchers say they reproduced the behavior with the latest models, Opus 5.5 and Fable 5.1. Their scan, their count. Deleting the file does not undo the leak - older versions live on in git history and forks - so the advice is rotate first, clean second. This lands in the middle of Claude Code’s roughest week: the email-in-User-Agent issue (No. 034) is still open with no official Anthropic statement beyond one team member’s comment, and users there are already demanding the feature be ripped out rather than modded.

✂️ STEAL IT

Steal the audit: search your own repos - and your org’s - for settings.local.json before someone else does. And steal the design lesson: any "remember this decision" feature that stores raw user input verbatim will eventually store a secret verbatim. Store the pattern, never the literal command.

Try today  VERDICT

Do the TRY section below: hunt the file in your repos, rotate anything you find, then clean history. It fails you if you have never clicked "don’t ask again" on an exact command - and only you can check that.

02  hunch.net, Nov 6 · HN: 423 points at 06:26 IST

🏁 "We did good work and were non-consensually reorged away" - the end of Microsoft’s AI Frontiers

John Langford - reinforcement-learning researcher, Vowpal Wabbit author - quit Microsoft and declared the AI Frontiers group he founded in 2023 finished, in a first-person post. The ~50-person group built Autogen and the Fara computer-use agent.
SCENE

In 2023, after ChatGPT shipped, Langford concluded that one researcher with one clever idea would now always "arrive late and unconvincing" - the baselines one person can assemble are too weak. So he and colleagues organized AI Frontiers inside Microsoft Research: about fifty people who built things you have heard of - the Autogen orchestration framework, the Fara computer-use agent - alongside fundamental work he names: the Next Latent objective, Dion3 (his "optimized/improved Muon"), and a Full Bandwidth Transformer that, he writes, ByteDance’s experiments suggest might match a model twice its size.

THE THING

His account of the ending is blunt. "So I situated my folks as best I could and left." Every other founding AIF leadership team member, he says, seems to have come to a similar conclusion. On why not return to plain MSR: the research had "no path to real use" in Microsoft AI, and "I’m afraid there’s a breakdown of the basic deal in MSR: do good work and good things happen. As far as I can tell we did good work and were non-consensually reorged away." He does not say what happens to Autogen, Fara, or the group’s headcount now. Microsoft has not posted its own account; everything here is his side, in his words.

✂️ STEAL IT

Steal the org lesson: his diagnosis for why small research groups die is specific - compute bottlenecks, no path from research to product, and a parent org that reorganizes without consent. If you run a researchy team inside a big company, his three failure modes are a checklist worth reading against your own quarter.

Watch  VERDICT

Read the post itself - it is short, first-person, and the quotable lines are earned. It fails you if you want Microsoft’s side or a headcount accounting; neither exists yet.

03  anthropic.com engineering, Nov 6 · HN front page

🧠 Anthropic opens up Claude’s memory: dreaming sessions took wiki answers from 13% to 48%

Anthropic’s engineering post "The components of agent memory" describes how Claude’s memory works - and says that scaling "dreaming" from 2 to 128 sessions raised performance on its 25-question wiki evaluation from 13% to 48% of graded criteria. Their evaluations, their numbers.
SCENE

Claude plays Pokémon with a memory folder. In Anthropic’s telling, Sonnet 3.7 wrote 413 memory files across 225 folders - a separate file per battle, per item, per NPC - and earned one badge. Fable 5 wrote nine files in two folders plus a single top-level global.md, and earned four. The messier archive was not the better memory; the smaller, organized one won. That contrast is the whole post in miniature.

THE THING

The post’s spine: agents capture work in logs and transcripts, and a separate offline process - "dreaming," echoing the hippocampus replaying experiences during sleep and the sleep-time compute idea from Letta and UC Berkeley - replays those logs to fix mistakes, merge duplicates and reorganize notes. Anthropic says that scaling dreaming from 2 sessions to 128 grew accuracy on its 25-question wiki test from 13% to 48% of graded criteria, with the wiki built incrementally and pruned as it went. It also points at Continual Learning Bench (CL-Bench) 1.0 for long-horizon memory tasks. All of these are Anthropic’s own evaluations of its own models; no external replication exists yet.

✂️ STEAL IT

Steal the pattern for anything you build with agents: raw transcripts are capture, not memory. Budget a consolidation pass - offline, on idle time - that turns logs into a small organized store, and expect the organizing to matter more than the volume. The 413-files-vs-9 result is the anecdote to cite when someone proposes "just dump everything in the folder."

Try today  VERDICT

If you run agents with file-based memory, read the post’s dreaming section and copy the two-store split: append-only capture, plus a consolidated store that an offline pass owns. It fails you if your agent’s tasks are single-session - there is nothing to consolidate.

🧪 ONE THING TO TRY TONIGHT
Rotate first, then clean.
Fifteen minutes, and start with rotation - not deletion. First: find the file. In every repo you have ever used Claude Code in, look for .claude/settings.local.json; then search GitHub for public copies tied to you or your org (apiiro found 1,122 - one of them could be yours). Second: if a file holds any password, token or key, rotate it now - change it at the provider, because deleting the file leaves the secret readable in git history and forks. Third: only after rotation, remove the file and scrub history (git filter-repo, or delete and recreate the repo if it is yours and young). Finally, going forward: when Claude Code offers "don’t ask again" on an exact command containing a secret, say no - approve the pattern, never the literal.
