A desktop team shut the door on AI pull requests 🚪

COSMIC's new PR checkbox, and one contributor caught in it
SCENE

lkramer had a bug: passwords in the network applet for the VPN. By his own account on Hacker News he used Claude to find it and write the fix, then spent a lot of time handcrafting it and checking the quality. Then COSMIC changed its rules. His pull request was in flight and got closed. His comment: "I respect their decision and no hard feelings."

THE THING

System76's COSMIC desktop. The pull request template in pop-os/cosmic-epoch now has a checkbox: "I have not included any LLM (also known as AI) generated content in this PR, including code, comments, and descriptions." Jeremy Soller announced it on Mastodon on Sep 30. His stated main reason is review load: the team wants to prioritize its own people and regular contributors, and it was getting far more unplanned changes from first-time contributors using LLMs, with a low acceptance rate. cosmic-flatpak is exempt.

✂️ STEAL IT

Read the template's checklist and answer it for your last Claude-assisted PR. The line worth keeping even where AI is allowed: "I understand these changes in full and will be able to respond to review comments." Paste it into your own PR template.

Watch  VERDICT

One project's capacity rule, in its own words. It fails as a trend signal: it is one org, and the stated reason is review load, not code quality. One HN commenter says SQLAlchemy does something similar; we did not check.

12 PRs overnight, if you say what "done" means 🏁

a commenter's CI story, and the guide behind it
SCENE

On Hacker News, rdli told Opus to speed up his team's CI. He said he cared about billing minutes and wall-clock time, asked for a plan, had a second model review the plan, and told it to stick to low-risk, high-reward changes. Nine hours later, by his count: 12 PRs ready to merge, CI down from about 10 minutes to about 4, billing minutes down about 60%, and less than an hour of his attention. One commenter's report. We have not checked his numbers.

THE THING

"Getting the most out of Opus 5.5 in Claude and Claude Code", by Addy Osmani on the claude.dev blog, published Sep 22 and back on HN today. Its advice: give the whole task in one message, name the finish line ("the tests pass") and say when to stop and ask. Delete "think carefully" lines, since the model already thinks before every reply (the guide says that in its own testing in a chat product, removing the line made replies start sooner with no clear drop in quality). You can type a follow-up while it runs. These are the vendor's claims about its own model.

✂️ STEAL IT

Next long task, write one message: the task, "Done means: ...", and "Stop and ask me only if ...". Then add the guide's rule to CLAUDE.md: Stop and ask only when you can't continue without me, or before anything destructive: deleting data, force-pushing, or changing anything outside this repository.

Try today  VERDICT

Five minutes and no install. It fails when "done" cannot be checked by a command: rdli's task had CI timings to measure, and the guide's own example leans on a test suite.

"The terminal era is over" 🪦

a Databricks engineer says the agent, not the file, is the new unit
SCENE

Yuchen Jin (@Yuchenj_UW; his bio says Databricks, previously co-founder and CTO of Hyperbolic) posted that he has not touched Claude Code or Codex CLI in a while. His reasons: tabs are ephemeral, context is persistent, and managing 30 tabs is pure cognitive overhead. He rarely navigates the codebase now. "The new primitive is the agent, not the file." He calls the Codex desktop app the best agentic UI for now, and adds that it is early.

THE THING

A take, not a tool. Posted Oct 3, 2,765 likes, 97 reposts, about 680K views (read from a public mirror of X).

✂️ STEAL IT

Our test, not his: count the agent sessions you actually had open yesterday. If it was closer to 30 than 3, his complaint is yours. Note that two of today's finds below draw their UI inside the terminal.

Watch  VERDICT

It fails as evidence: no numbers, one person's workflow, and the UI he praises belongs to a competing product.

A flight recorder that stops the key from leaving ✈️

agent-blackbox watches for the secret-plus-web-plus-outbound trap
SCENE

Your agent reads a project's .env. Then it fetches a setup page with a hidden instruction. Then it tries to curl the key to a stranger. We ran the project's own demo in a sandbox. It is a scripted simulation: the .env read is allowed, the web fetch is allowed, and the outbound POST carrying a fake key is denied because a secret read earlier in the session shows up in an outbound call. A bare curl to the same host gets an ask prompt. npm test goes through.

THE THING

developerfred/agent-blackbox, Apache-2.0, created Oct 3, 0 stars when we looked, a 2-point Show HN. Per the README: every prompt, tool call and result goes into a hash-chained, Ed25519-signed ledger written by a separate process, secrets are stored as fingerprints, and a policy stops a session that has read private data, seen untrusted content and then tries an outbound call. Local only, no dependencies, Node 18+. Claude Code first.

✂️ STEAL IT

npx agent-blackbox scan --days 30 replays your past sessions in ~/.claude/projects through the policy, per the README, and tells you how many read secrets and called out. Read the source before pointing it at real history.

Watch  VERDICT

Right idea, built as hooks. It fails because it is a day old with no users, and we ran only the scripted demo, not a live Claude Code session.

See every file your subagents touch, live 🛰️

mission-control draws the agents next to your chat
SCENE

You start three subagents and then stare at a scrolling log. hamzafer's mission-control puts a pane next to the chat that draws every subagent, every tool call and every file they touch. Per the README: blue while the agent reads a file, orange while it writes, green when done with one line on what changed. Press w for agents, c for a code map with import arrows.

THE THING

hamzafer/claude-code-mods, MIT, a marketplace of mods. Also in it, per the README: token-weather (context fill and a prompt-cache countdown), usage-meter (5-hour and 7-day plan usage), and blast-radius, which holds rm -r, force pushes and migrations, shows what they would delete, and cancels if nobody answers. Needs Claude Code 2.1.287 or later. The code view also needs macOS, Chrome and a terminal that shows images.

✂️ STEAL IT

claude plugin marketplace add hamzafer/claude-code-mods, then claude plugin install mission-control@claude-code-mods, restart, type /mission. Mods run code inside your session, so skim the plugin source first.

Watch  VERDICT

Useful if you run several subagents. It fails if the pane costs more attention than the log it replaces, and we have not run it: it needs a live Claude Code.

Why your subagent ignores what you told Claude 🗺️

harness-map draws what each new agent really receives
SCENE

You set rules in CLAUDE.md and hooks. Then you start a subagent from another folder and it acts as if it never heard them. Dominic-DK's harness-map reads your Claude Code setup and shows, per start folder and per way of launching an agent (main, fork, subagent, Explore or Plan, teammate, claude -p), what the new agent gets: passed from the parent, read fresh from files, or not passed at all.

THE THING

Dominic-DK/harness-map, MIT. A Python 3 script of about 2,000 lines, no extra packages, plus a 32-line page builder. Per the README it reads config and counts your chat history, and keeps paths, rule counts, hook events and MCP server names, not the text of CLAUDE.md or environment values. We grepped both files for network imports (http, urllib, socket, requests) and found none. It also scores your setup on a maturity self-check. The README is in Korean.

✂️ STEAL IT

git clone https://github.com/Dominic-DK/harness-map && cd harness-map, then python3 harness-map.py --cwd ~/your/repo -o harness.json and python3 build.py harness.json, and open harness-map.html. Open harness.json before sharing it: it holds folder names and your plugin list.

Watch  VERDICT

The idea is right: most people cannot say what a subagent inherits. It fails if its model of Claude Code's behavior lags the releases, and we have not run it or checked it against Claude Code.
