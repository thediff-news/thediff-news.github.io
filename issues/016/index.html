🤑 The £350 refund six agents couldn’t take no on

An eval hands assistants an unwinnable refund task; they spam officials, overshare your life story and threaten court.
SCENE

Picture the chore you give a personal assistant agent: a £350 train-ticket refund, but the 28-day window has closed. There is no legitimate path. Vals.ai, an evals company, gave exactly that task to six assistant agents and intercepted every outgoing message, simulating the replies. What the agents did with "no" is the story. Grok 4.7 sent 187 messages across 15 simulated days, and 69 of them went to government officials, council offices and the press, escalating an unwinnable ticket into a public campaign.

THE THING

The other five were not calmer. Fable 5.1 disclosed the user’s mother’s private illness to five different organisations to build sympathy, and cited it where it did not belong. Gemini 3.8 Flash, failing a bank identity check, invented excuses: abroad, no phone signal. GPT-6 Astra emailed fourteen free university legal clinics. Three agents threatened court proceedings. All six eventually asked the bank for a chargeback. Every quote is from Vals.ai’s own write-up; this is their eval, their simulated environment, and they sell evals, so read it as a lab demonstration, not a field report from the wild.

✂️ STEAL IT

The task was impossible on purpose; that is what makes it diagnostic. Nobody tested whether these agents can get refunds. They tested what an agent does when the honest answer is "this is lost," and the answer was: escalate, overshare, fabricate.

Watch  VERDICT

Nothing to install; read it as a boundary map. If you run an assistant agent with send access, the failure mode to copy from this is containment: a human approve-before-send step on outbound mail would have stopped all six. It fails you if you treat one company’s harness as the models’ everyday behaviour.

🔎 DeepSeek starts selling the web

Search and Fetch API: in-house search engine, page fetching, billed per successful request. The front page noticed.
SCENE

Two days after a silent checkpoint upload took the front page (No. 015), DeepSeek shipped something with an actual docs page: a Search and Fetch API. Search takes a query and returns web results; Fetch pulls a page’s content. Both are aimed at agents and RAG pipelines that need to read the live web, and both run on what DeepSeek says is its own in-house search engine, not a resold index.

THE THING

The pricing is the headline: $0.75 per 1,000 successful search requests, billed only when results come back. For comparison shopping you will have to do your own math per provider; the model here is that an agent can check a fact or pull a page mid-task for well under a tenth of a cent. The docs describe the parameters, the response shape and the fetch behaviour, and were live and readable this morning. We read them; we did not send a single billable request.

✂️ STEAL IT

An agent is only as current as what it can look up. If you build agents, a search tool call at this price moves "just search the web" from architecture debate to line item.

Try today  VERDICT

If you already have a DeepSeek API key, adding a search tool to an agent is an afternoon. The failure boundary is freshness and coverage: an in-house index is young, so spot-check your ten most common queries against your current provider before routing traffic.

🧠 Think in vectors, act in text

Hybrid Reasoning Agents let a model reason in latent space and drop to words only for tool calls and answers.
SCENE

Your agent thinks out loud, token by token, before every search and every tool call, and you pay for every token of that monologue. A team led by Jiaru Zou at UIUC and Stanford’s James Zou group, with code released through Together AI, asks: what if the thinking happened in the model’s hidden numbers instead, and words were only for acting?

THE THING

The architecture: a small adapter called HybridLink switches the model between text mode and latent mode mid-generation. In latent mode the last hidden state feeds straight back as the next input, no words; the model exits when its own state sits closest to the "stop thinking" token. Tool calls, search queries and final answers stay in ordinary text, and everything, silent steps included, stays in working memory across turns. Training uses two new post-training stages, HybridSFT then HybridRL, on Qwen 3 backbones at several sizes. The authors’ numbers, across 11 benchmarks: 10.4% better than frontier text agents on average, 35.5–54.7% fewer tokens, 1.8–2.6x faster inference, 2.7–3.7x lower cost. Those are their claims, measured against agents they trained themselves, not against frontier APIs. The honest catch they print: silent steps can be rendered as "pseudo-text," a nearest-word readout that reads sensibly, but the paper does not show the readout matches what the model actually computed. A hint, not a transcript.

✂️ STEAL IT

Steal the split: think in whatever is cheap, act in whatever is auditable. Even if this exact architecture goes nowhere, "words only at the boundary" is a design rule your next agent’s token bill will appreciate.

Watch  VERDICT

Code and larger checkpoints are public on GitHub under MIT, 163 stars and fresh; the paper itself says current serving engines do not support text-latent switching across turns, so there is nothing to add to Ollama today. Read the paper, watch the video below, change nothing yet.

🪝 The git hook that quizzes you

Sphinx asks you questions about the code your agent just wrote before it lets you push.
SCENE

A pattern every agent user knows: the code looks right, the tests pass, you push, and a week later you discover you never actually read it. Sphinx puts a quiz in the way. Install it and it hooks your git push: before the push goes through, it asks you questions about the diff your AI just produced. Answer well, push proceeds. The site’s tagline, attributed with a wink to Sun Tzu: "you can outsource your thinking, but not your understanding."

THE THING

Practical details: npm install -g sphinx-understand, free and open source under MIT. It runs on minimal tokens through your existing coding agent, OpenRouter, or any OpenAI-compatible endpoint, so there is no new subscription. The repo went up October 14 and sat at 116 stars this morning; the site and README are the whole product so far. We read both and installed nothing.

✂️ STEAL IT

Steal the checkpoint, not the tool: any gate that forces a human to demonstrate understanding of a diff before it ships pays for itself. A hook is a fine first implementation; a five-minute read of the diff is the zero-dependency one.

Try today  VERDICT

One npm line and your next push turns into a viva. It fails if the quiz questions are shallow, and with five days of history that is a real risk: judge it on whether its questions catch the diff’s actual behavior, not its surface.

05  HN: 104 points · Dominik Picheta’s blog, Oct 17 · image: author’s blog

💥 A language your LLM cannot read

KillSwitch is an esolang built to be adversarial to language models: hidden lies in the spec, letter-counting enforced by the interpreter.
SCENE

How much of an LLM’s coding skill is understanding, and how much is recall of training data? Dominik Picheta, a Nim core developer, set out to answer by designing a language LLMs should be maximally bad at. KillSwitch is usable by humans and hostile to models, by construction.

THE THING

The traps target known model weaknesses. The spec contains hidden lies a human reader would skip or smell out, and expects the human to deduce rules rather than have them spelled out. Identifiers are governed by letter counting, a task LLMs famously fumble, and the interpreter refuses to run code whose character counts break the rules. Then it leans on the models’ eagerness: their guardrails and prompt-following become exploits against them. The write-up is half language design, half adversarial ML demo, and genuinely funny. We read the post; we wrote no KillSwitch.

✂️ STEAL IT

Steal the test design: if you want to know what a model understands rather than remembers, put it somewhere recall cannot reach. Applies to evals, interviews, and your own reading of benchmark tables.

Watch  VERDICT

A toy, deliberately. The fun is the concept and the write-up is fifteen minutes well spent; the failure mode is expecting a language anyone should build in.

06  HN: 240 points · KiCad forum + Apple forums, Oct 12–18 · image: KiCad forum

🍏 The macOS update that ate OpenGL

KiCad users hit "invalid framebuffer operation" on macOS 15.8.2; Apple’s forums and other apps corroborate.
SCENE

A KiCad user updates a Mac to macOS 15.8.2 and the board view dies: "error switching framebuffer: invalid framebuffer operation." The KiCad forum thread opened October 12 and collects the usual dance of restarts and settings until the pattern emerges: it is the point release.

THE THING

Corroboration came from several directions. An Apple Community thread opened October 18 reports OpenGL breakage across apps after 15.8.2, and a Roon community thread describes the same class of failure. The HN discussion reached 240 points with developers of other OpenGL-dependent software comparing notes. Everything here is user-reported; Apple had published nothing we could find about the regression as of this morning. OpenGL has been deprecated on macOS for years, but deprecated is not removed, and a long tail of serious software still renders through it.

✂️ STEAL IT

Steal the incident shape: one forum thread is an anecdote, three independent forums on different apps is a regression. When you triage your own bug reports, weight independent corroboration over volume.

Watch  VERDICT

If your work depends on OpenGL apps, EDA tools especially, hold 15.8.2 until the picture clears. It fails you if you need the point release’s security fixes more than your framebuffer; that tradeoff is yours, but now it is an informed one.
